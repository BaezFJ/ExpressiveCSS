# Governance

ExpressiveCSS is owner-led. [BaezFJ](https://github.com/BaezFJ) has final authority
for design decisions, community moderation, merges, and releases. Contributors
propose changes through public discussions, issues, and pull requests.

## Work and decisions

The [ExpressiveCSS community Project](https://github.com/users/BaezFJ/projects/8) is the shared board. Its columns are Backlog,
Ready, In progress, In review, and Done. Issues contain acceptance criteria; PRs
link to issues. Release milestones express intent, not deadlines.

BaezFJ confirms scope before marking substantial work Ready. A contributor claims
work in the issue, moves it to In progress, and opens a draft PR early when review
would avoid wasted effort. Ready-for-review PRs move to In review. Done means the
accepted change is merged; release notes identify when users can install it.

Use Discussions for questions and proposals. Major API and design decisions need
an accepted discussion before implementation and an ADR when architectural.
Record decisions and their reasoning publicly, including when a proposal is declined.
Security and conduct reports use the private channels in their respective policies.

## Reviews and maintenance

BaezFJ reviews community PRs and any relevant screenshot reports. His own PRs
require passing CI but no second reviewer while the project has one maintainer.
CODEOWNERS requests review; it does not itself enforce approval.

BaezFJ reviews the board weekly and posts a monthly progress discussion covering
completed work, current priorities, and decisions. Contributors should comment
when work is blocked or they cannot continue, so it can be reassigned.

Trusted contributors may become maintainers after sustained useful contributions
and a public proposal accepted by BaezFJ. Document their areas and access before
granting permissions. Require independent approval once a second active maintainer
can review. Review repository and npm access quarterly; use 2FA and keep recovery
methods outside the repository.
