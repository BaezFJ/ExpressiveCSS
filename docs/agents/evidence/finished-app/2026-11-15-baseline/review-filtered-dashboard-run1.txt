CHECKED
- Lifecycle: the bundle is a classic script at the end of `<body>` and runs after the markup exists. There is one `AutoInit(document.body, { Tabs: { onShow } })` call, no manual `.init()`, no `no-autoinit` mixing and no global `M`. DataTables is shared runtime, and rows are created before `setPage(wrapper, null)` → `sync`, which re-runs filter and paging (confirmed in dist/js/expressive.js:4971-4999). Nothing is removed without teardown.
- Assets and fonts: one local stylesheet; dist/css and dist/fonts are both present. There is no Google Fonts or Material Icons link and no `.material-icons` markup. Icons use `.material-symbols` with `aria-hidden="true"`. The JS bundle is needed (Tabs, DataTables) and does not block rendering in `<head>`.
- States: the table has an empty state that names the state and query, and its Clear filter button returns focus to the input. The pager hides when there are no matches. The page buttons get `aria-disabled` from the framework at the edges. Data is generated synchronously in the page, so no loading or error state applies. No custom CSS removes focus rings, and no native control is disabled with a class.
- WCAG names and semantics (source): every icon button and the Help button have accessible names. The filter has a `<label for>`. The count and page status outputs are named, `role="status"` and `aria-live="polite"`. The scroll region is `role="region"`, focusable and labelled by the caption. Sort buttons are inside `th` with `aria-sort` on the header. There is a skip link, and `<main tabindex="-1">` is the target. Tabs are native links, which keeps them keyboard reachable.
- Reduced motion: the page has no custom animation. The Tabs indicator uses the default spring, which stops under reduced motion according to the Tabs guide.
- finished-app:loading: not applicable, because no command runs a request in script.
- finished-app:destructive: not applicable, because there is no remove or discard action.
- finished-app:submit-flow: not applicable, because there is no form. The single search filter applies as you type, and its `autocomplete="off"` and `type="search"` are appropriate.

BLOCKED

HANDOFFS
- Page architect: the header puts `<h2>Northwind store</h2>` before the page's `<h1>`. It also uses `<nav aria-label="Workspace">` around a heading and a command button with no navigation links, which goes against accessibility rule 3 (no `<nav>` for app-bar commands). Consider an app bar `<header>` without `nav`.
- Component syntax expert: the header Help button is a bare `<button>` holding only an icon. Check whether it should be an `.icon-button` like the pager buttons.
