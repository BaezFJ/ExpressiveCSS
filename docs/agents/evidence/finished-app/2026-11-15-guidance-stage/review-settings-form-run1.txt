The page calls `Expressive.Forms.validateField` directly, as documented, and uses no retired global `M`. Nothing is removed dynamically, so no `destroy()` is owed.
- Assets and fonts: one framework stylesheet, and `dist/fonts/` sits next to `dist/css/`. No Google Fonts links, no Material Icons stylesheet, no `.material-icons` markup, no unused icon fonts. The JS bundle is justified because the page uses `Forms`. The script is not in `<head>`, so it does not block rendering.
- States: the save button is a native `<button type="submit">`. `aria-disabled="true"` while pending gets the framework's disabled styling (dist/css/expressive.css:2597-2606). Re-entry is blocked by the `pending` flag, not by `disabled`, which is acceptable because the button keeps focus. The page's CSS does not remove any focus ring. `[hidden]` reliably hides the indicator because the framework sets `display:none !important` (expressive.css:1362). Error and success states both exist. There is no list, table or async content load that would need an empty or loading state.
- WCAG names and labels: every input has `<label for>`, and every help `<small>` has an id referenced by `aria-describedby`. `Forms._describeByError` adds the `[data-error]` element, so the error text is described with its field. `aria-invalid` is set by `validateField` and by the server-error path. The fieldsets have legends. `lang` is set. No icon-only controls. The header is not sticky, so 2.4.11 is not at risk from source.
- finished-app:loading: the label stays action-named ("Save", then "Saving…" with the `…` character). A `.loading-indicator` appears beside the button after 300 ms and stays at least 500 ms. A second press or Enter is ignored through `pending`. Passes.

A failed client check focuses the first invalid field, and a server rejection marks the email invalid and focuses it. Paste is not blocked. `name` is present on every field. `autocomplete` is set: `nickname`, `url`, `email` and `tel`. `type` is `url`, `email` and `tel`. `spellcheck="false"` is on email and url. Floating-label `placeholder=" "` passes. Passes.

- Focus-visible rendering on the inputs and the save button, including while `aria-disabled` is set. Needs rendered evidence.
- Target size of the filled button (WCAG 2.5.8 minimum and the 48dp recommendation). Default button geometry is likely above 24×24 but was not measured.

- Whether the live announcements for "Changes saved." and the failure messages are actually spoken. Source shows `role="status"` with `aria-live="polite"` on an element that starts empty, which is correct, but delivery needs assistive-technology testing.
