CHECKED
- Lifecycle: no `AutoInit()` is called and no registry component needs it. The tooltip is the plain CSS-only form, and Snackbar and Forms use shared runtime paths. The script sits at the end of `<body>`, after the markup. There are no `.init()` calls, no `M` global, and no manual instances that need `destroy()`. `pagehide` sends pending deletes and calls `Snackbar.dismissAll()`.
- Assets and fonts: one framework stylesheet, no Google Fonts or Material Icons links, and no `.material-icons` markup. Icons use `.material-symbols` with `aria-hidden="true"`. The JS bundle is needed and loads at the end of the body. Whether `dist/` exists on disk was not checked (out of scope).
- States: double click on delete is ignored (`event.detail > 1`). The empty state is wired to the list count. No class-based disabling and no custom focus-ring removal. The data is inline with no initial fetch, so no list loading state is needed. A failed delete is reported and the item restored.
- WCAG names: the icon button gets `aria-label="Delete <label>"`. Add, Cancel and Save have visible text. The dialog is labelled by its heading. Every input has `<label for>`. Help text is linked with `aria-describedby`.
- Keyboard: after a delete, focus moves to the neighbor or the empty-state button. Undo focuses the restored row. Escape is guarded during save.
- finished-app:destructive: delete takes effect at once with an Undo snackbar (`action` + `onAction`, `replace: true`). Undo restores the item in place through its preserved `seq`. The commit runs on `completeCallback`, and a second delete cuts the first one short and commits it. Passes.
- finished-app:submit-flow: Save is not disabled before submit. The fields are inside `<form>` and Save is tied to it with `form="add-form"`, so Enter submits. A failed submit focuses the first field with `aria-invalid`. No paste blocking. `name` is set on every field. Address fields have `autocomplete` (`address-line1/2`, `address-level1/2`, `postal-code`). The "Name" field is an address nickname, not one of the listed input purposes. Postal code has `spellcheck="false"`. Floating-label placeholders are `" "`.
- finished-app:loading for the label and double press: "Saving…" ends in `…`, and the `aria-busy` guard stops a double submit. Only the missing progress is reported above.
- finished-app:url-state: not applicable (no tabs, filters, search or paging).

BLOCKED
- Contrast (header supporting text in `on-surface-variant`, snackbar, tooltip), focus visibility, and target size of the `.icon-button` delete control (2.5.8) need rendered measurement. No browser route.
- Error rendering and association: `Expressive.Forms.validateField` and `data-error` are not documented in the bundled guides. I could not confirm from source whether error text is rendered, linked to its field (3.3.1, 1.3.1), or keeps the existing `aria-describedby` help ids.
- Whether the Undo snackbar takes focus when shown with `replace: true`, and whether its text is announced. The guide only says queued snackbars take focus, and spoken delivery is unverified upstream.
- Whether the save-failure snackbar is visible above the modal dialog's backdrop. The finding above is inferred from source.
- 1.4.13 dismissibility and hoverability of the CSS tooltip on the delete button: there is no Escape handler in source, and behavior needs a browser.
- Undo restoring the row in place is inferred from the `seq` sort and not watched in a browser. 2.4.11: no sticky header in source, and the snackbar covering a focused last row is unmeasured.
- Reduced-motion handling of snackbar and dialog transitions is framework-owned and needs a browser.

HANDOFFS
- Component syntax: the `<span class="tooltip">` built at line 149 has no `id`, and the button has no `aria-describedby` pointing at it (`css-tooltip-is-described-by`). Lint missed it because the markup is created in script.
- Component syntax: the dialog's Cancel/Save row is a second `<form method="dialog">` holding a `type="button"` and an external submit button, so the `method="dialog"` form does nothing. Check the documented dialog action markup.
