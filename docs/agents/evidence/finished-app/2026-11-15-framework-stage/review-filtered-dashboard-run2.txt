FINDINGS
- [major] index.html:253-258 (`.clear-filter` click handler) together with index.html:239-243 (debounced filter URL write) | source | finished-app:url-state | The Clear filter handler writes `q=''` at once but doesn't cancel the pending `typing` timeout. Say someone types a query that matches nothing, the empty state appears, and they press Clear filter within 300 ms. The old timer then fires `writeUrl({ q: <old query> })`, which writes the cleared query back into the URL. The field is empty but the URL still holds the old filter, so a reload or a shared link brings back the filter the user cleared. | Call `clearTimeout(typing)` in the clear handler before `writeUrl({ q: '', page: '' })`. Better still, have the input handler cancel the timer and write the URL right away whenever the trimmed value is empty.
