CHECKED
- Lifecycle: the script sits at the end of `<body>`, so the markup exists before it runs. The panel tables are cloned and filled before `Expressive.AutoInit()` runs once on DOMContentLoaded. There is no manual `.init()`, no retired global `M`, and no dynamic remount, so `destroy()` is never needed. Restoring `.active` before AutoInit lets Tabs start on the saved tab.
- Assets and fonts: dist/css/expressive.min.css, dist/js/expressive.min.js and dist/fonts/ all exist with fonts next to css. There are no Google Fonts or Material Icons links and no `.material-icons` markup. Only the outlined `.material-symbols` family is used. The JS bundle is justified because Tabs and DataTables use it. No render-blocking script is in `<head>`.
- States: no custom CSS removes the focus ring. There are no class-disabled native controls. The framework sets `aria-disabled` on page buttons at the ends and ignores presses there (expressive.js:5120, 5166-5170). Empty states exist for filtered-out rows. Clicking "Clear filter" moves focus back to the input, so focus isn't lost when the empty state hides. The data is local and synchronous, so loading and error states don't apply.
- WCAG names and labels: the search field has a `<label for>` and a description through `aria-describedby`. The icon-only page buttons have `aria-label`. Decorative icons are `aria-hidden`. Tab badge counts are repeated in each tab's `aria-label`, and that label starts with the visible text (2.5.3 OK). The scroll regions have `role="region"` and `aria-labelledby` pointing at the caption. Status outputs are named, polite and `role="status"`. The skip link goes to a focusable `<main>`.
- Keyboard and motion: tabs, sort buttons, page buttons and the scroll region are all reachable by keyboard. There are no custom animations, and the Tabs indicator stops under reduced motion according to its contract.
- finished-app:url-state for tab and filter: both use `replaceState` (filter debounced by 300 ms, cleared on "Clear filter") and are restored on load from `view` and `q`. Panel hashes are removed from the URL. No `pushState` is used, so Back stays consistent. Sort is out of scope.
- finished-app:loading: not applicable, because no command runs a request in script.
- finished-app:destructive: not applicable, because there is no remove or discard action.
- finished-app:submit-flow: not applicable, because there is no form or submit. The live filter field has `name`, `type="search"`, `spellcheck="false"` and the floating-label `placeholder=" "`, and its purpose is not on the input-purpose list.
