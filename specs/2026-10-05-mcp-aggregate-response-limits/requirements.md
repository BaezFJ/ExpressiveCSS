## Metadata and failure implementation choices

Use one shared budget record and typed omission/recovery records, extending existing per-tool schemas as needed. Do not create another response formatter. Tests must inspect advertised schemas and reject malformed metadata, negative counts, unknown omission reasons and unsupported recovery arguments.

Measure the final serialized result after every reduction. If metadata itself prevents delivery, return a smaller truthful error or the specified protocol failure. Do not drop omission records while claiming complete accounting. Internal byte metrics are optional; if exposed, they must equal the final measured result including their own serialized size.

Catalogue recovery can use an exact slug query rather than adding pagination. Search-limit recovery retains existing query/limit behavior. A giant Options section cannot be recovered by silently slicing it; return the operator-increase error when narrower selections cannot fit. New resource-read recovery is unavailable until Phases 8 and 9.

## Implemented choices

`responseBudget` reports `maxBytes`, `delivery`, `omissions` and `recoveries`. Omission records identify a whole unit and reference typed retry or operator-increase advice. Syntax results add `requestIndex`; field reasons retain selector distinctions and add `length-limit` and `byte-budget`. Partial/error status and coverage describe actual delivery. Guidance text uses compact JSON while QA serialization retains its existing formatting.

Syntax, catalogue and creative recovery sizing reuses the same pure response builders as ordinary requests. Syntax recovery offers a narrower complete projection that fits the same budget. Creative recovery reranks an exact named-component goal with one suggestion. Catalogue recovery preserves an explicit target and omits the optional workflow correlation ID because that retrieval has no workflow state. Complete accounting that cannot fit becomes a whole-request error with no delivered guidance.

The stdio send check runs after SDK error handling and replaces oversized scoped results with JSON-RPC error `-32001`. This also covers SDK input/output validation errors and disabled-tool results. No dependency, generated data, framework behavior or QA policy changed.
