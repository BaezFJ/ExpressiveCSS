Commands: `npm run build`, then `node --test tests/scroll-area.test.js` for the jsdom checks and `EXPRESSIVECSS_TEST_BROWSER=<engine> node --test tests/scroll-area-horizontal-browser.test.js` once per engine for the browser checks. Phase 101's validation recorded these command forms as run. The new file name is not verified until the file exists.

Browser checks use a 600 by 500 window. Three container fixtures recur, each `<div id="box" class="scroll-area custom" style="block-size: 300px; inline-size: 240px">` with one child and no border or padding:

- Two-axis: the child is 900px tall and 720px wide. Both bars are displayed, the corner is 12px, the vertical track is 288px with a 96px thumb and 192px of travel, and the horizontal track is 228px with a 76px thumb and 152px of travel. The scrollable distances are 600px and 480px.
- Sideways: the child is 100px tall and 720px wide. Only the horizontal bar is displayed, with a 240px track, an 80px thumb and 160px of travel, so one pixel of pointer travel scrolls 3px.
- Upright: the child is 900px tall and 100px wide, which is phase 101's fixture.

The page fixture is a document 1,500px tall and 1,800px wide, on `<html class="scroll-area custom">`. An x coordinate in a row is measured from the bar's left edge, and a y coordinate from its top edge.

jsdom checks set `clientHeight` 300, `scrollHeight` 900, `clientWidth` 240 and `scrollWidth` 720 on the scroller unless a row says otherwise. They stub a recording `ResizeObserver`, the frame queue, and `scrollTo` and `scrollBy` on the container and the window. A row that needs a corner supplies a 12px bar width through whatever the implementation reads.
