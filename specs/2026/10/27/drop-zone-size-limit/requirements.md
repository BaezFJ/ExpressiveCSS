Phase 73 depends only on that merged work. These are agent decisions grounded in project evidence, not personal user approval.

Use `data-max-size` on the native file input as an independent opt-in. Values are positive decimal safe-integer bytes, with surrounding whitespace allowed. A file equal to the limit passes. Missing, blank, zero, negative, fractional, exponent/hex, nonnumeric and unsafe values impose no size constraint. Invalid author hints do not break existing markup. Reuse the authored direct `[data-error]` area; optional `data-error-size` on that area localizes size feedback separately from the existing type data-error value. Preserve type-first precedence, one rejection notification and the existing Forms API. No upload or byte-content inspection is added.

## Requirements

- **R1. Independent per-file size constraint.** Enabled native file inputs inside their nearest drop-zone enforce valid data-max-size without requiring data-validate-types or a file list. Parse trimmed decimal digits as a positive safe integer of bytes; other values are inactive. Reject file.size strictly greater than the limit, never equal. Empty optional inputs remain valid and required-empty native invalidity remains effective. Unmarked inputs retain existing behavior. Disabled controls/fieldsets remain inactive; after scripted enabling or constraint changes, call Forms.validateField to refresh.
- **R2. Whole-selection native rejection.** One oversized file invalidates the complete selection and blocks ordinary native form submission. Keep every File in the native FileList and optional safely rendered list. Do not filter, replace, upload or accept a subset. Reuse phase 72 ownership: acquire explanatory native custom validity only when no unowned application error exists, mark invalid/aria-invalid, and preserve pre-existing or replacement application custom validity. Required, native validation bypasses and error-summary behavior stay intact.
- **R3. Shared accessible feedback and precedence.** Size opt-ins require the existing direct data-error area with role=status and aria-live=polite. Give it an id if absent and append that id once to existing aria-describedby. Write real text without moving focus. For combined constraints, a type failure wins and uses the existing type message; otherwise oversized files use nonempty data-error-size or a fallback naming the exact byte limit. Remaining native/application errors are reflected when no file rule fails; valid state hides/clears feedback. Reuse error/typography/focus styling for size-only zones. Preserve the existing static rule id while extending coverage, without component initialization.
- **R4. Shared delivery and event.** Native browse and drop selections share the input/change path in dynamic zones and open shadow roots. A changed size-rejected selection reports one bubbling, composed, noncancelable expressive:reject from the nearest wrapper with `{ input, files, rejected, reason: 'size' }`. Snapshots contain all files and only oversized files respectively. If types fail, preserve phase 72's reason:'type' and type-rejected subset. Native input/change pairs with the same files and effective constraints report once. Changes to the type opt-in, raw accept or effective size limit can report again after an input/change event. Silent Forms.validateField and reset report no rejection. Event-array mutation cannot corrupt deduplication; newer reentrant selection processing wins.
- **R5. Recovery and isolation.** Valid/exact-limit replacement, clearing, removing or invalidating the size limit followed by validation, and successful native reset clear only framework-owned file validity. Preserve unrelated application messages through rejection, recovery and reset. Canceled resets preserve files/list/error/drag state. Reuse deferred cancellation-aware cleanup, native form ownership including external associated controls, handled shadow-form reset and newer-selection protection. Type-only behavior remains compatible. Independent and nested zones remain isolated.
- **R6. Verified guidance and merge.** Update drop-zone docs, llm.md and changelog with size-only/combined examples, parsing/byte boundaries, message/event precedence, script refresh and server checks. Extend semantics and regenerate skill/MCP guidance. Review JS/CSS deltas against 109,246/90,893 gzip bytes. Run focused Node/browser/static tests, a size-comparison mutation, full contributor checks, MCP and clean package consumers. Inspect applicable docs and invalid size-feedback light/dark captures, complete independent review/fixes and separate simplification, then merge only after exact-head CI/conversation/current-master/clean-worktree gates pass.

## Scope and limits

Phase 74 owns file-count limits. No aggregate size cap, unit-suffix parser, upload, MIME inference, file filtering, runtime dependency, component or public export is added. File size metadata is not content validation and does not replace server-side checks. Physical OS picker/drop input, devices, native zoom and spoken screen-reader output are unavailable. Chromium protocol native-drop evidence is distinct from assigned FileList/input-change boundary checks in Firefox/WebKit. Keep roadmap labels unchanged here; the final separate documentation PR records completed phases, lasting rules and actual merge evidence.
