# Server-owned table paging requirements

Phase 71, 2026-10-27. Branch `feature/2026-10-27-server-table-paging`, base `8ed6a0f4d5416ff62ae9ab84df1decbf988e3675`.

Sources: [mission](../../../../mission.md), [technical constraints](../../../../tech-stack.md), [roadmap Phase 71](../../../../roadmap.md#phase-71-server-owned-table-paging), [server filtering](../server-table-filtering/requirements.md), [local paging](../data-table-paging/requirements.md), and [page size](../data-table-page-size/requirements.md).

## Evidence and delegated decisions

Phases 68 and 70 are merged. Phase 70 merged through PR #459 at the base after seventeen checks passed. Current paging stores a private numeric page and derives its total from visible DOM records. That would slice an already-paged response a second time, particularly when an application supplies page two. Native size changes currently deduplicate input/change by committing the wrapper size immediately; cancellation must retain accepted state without producing duplicate requests.

The user delegated planning, specification verification, implementation and feasible acceptance checks through feature-spec-auto, followed by incremental implementation, review/fixes, simplification and PR monitoring. The choices below are agent decisions, not personal user approval.

Add a silent atomic setter, `DataTables.setPage(wrapper, { page, pageSize, total })`, to accept an application-supplied page and opt that wrapper into server ownership. No new markup marker or component is needed. The application supplies the DOM records and any result-count text. A null state exits server ownership. Requests use the existing native page buttons and marked single select. Add `expressive:page` with `{ page, pageSize }`; local tables retain their default action unless canceled, while server tables wait for application state even if a listener does not cancel.

## Requirements

- **R1 — Accept authoritative state.** `setPage(wrapper, state)` returns true after silently accepting state on a `.data-table` containing its direct native table. Require numeric safe integers: page and pageSize positive, total nonnegative. Reject invalid/missing fields, numeric strings, fractions, infinities, unsafe integers and invalid target wrappers with false and no state, attribute, row or control mutation. Do not mutate the supplied object. Clamp an out-of-range positive page to the available range; total zero displays `0 / 0`. Reflect accepted pageSize in the existing wrapper attribute. `setPage(wrapper, null)` silently exits server mode and reapplies local paging from the first page using the current size.
- **R2 — Request before default paging.** Enabled marked page buttons and valid changed page-size controls emit one bubbling, composed, cancelable `expressive:page` from their own wrapper with a one-based requested page and pageSize. Clamp the requested page against the known total; a size request with no records requests page one. Without cancellation, local tables keep the Phase 69/70 default. Cancellation leaves accepted page/size, rows, order, selection, counts and focus unchanged; the user's native select value may already show the requested choice. Server tables never apply a local default or advance accepted state, including an uncanceled or unhandled request. Boundary/disabled controls and unchanged accepted sizes emit no request.
- **R3 — Apply responses without slicing.** Before the first request and after each synchronous or asynchronous response, accepted server state controls the page status and button bounds from the supplied total, never the DOM row count. Silent sync and setPage do not emit requests, filter, sort or selection events. Every supplied author-visible record remains displayed even on page two or when there are more supplied rows than pageSize. Details remain attached and consume no slots. A zero total changes controls, not application-provided records; applications render an empty body when their response is empty.
- **R4 — Preserve newer state and event delivery.** State accepted inside a listener and newer nested page requests supersede an older request's default action. The application owns asynchronous response ordering, errors and fetching. A native input plus its noncomposed change produces one size request even when canceled or deferred. Handle native composed input and FormSelect's composed change through the original select in documents and open shadow roots. Ignore the native noncomposed change duplicate; scripted changes use one bubbling composed input or change, as already documented. Keep invalid, disabled, multiple, unavailable-option and unrelated controls inert.
- **R5 — Keep server records application-owned.** In server mode, existing filter and sort events remain requests; they do not locally filter, reorder or reset the accepted page. Sorting keeps its existing requested aria-sort update. No extra page request is generated by filter, sort or sync. Preserve application count text, author-hidden/CSS-hidden records and details, expansion and checkbox states. Select-all affects enabled displayed records only and its existing event still reports selected DOM records. Removing server ownership preserves the separate Phase 68 canceled-filter contract. Independent/nested wrappers, ordinary pagination links and every local default remain compatible. Scripted wrapper-size updates plus sync remain silent; applications keep select/FormSelect presentation aligned, as in Phase 70.
- **R6 — Publish a verified contract.** Document the setter, null reset, state validation, request details, ownership and response-ordering responsibilities in the existing data-table docs and `llm.md`, and update the changelog. Reuse existing authored control/name/status rules; static semantics must never initialize components. Verify public declarations through existing package-consumer checks, regenerate guidance, review gzip deltas, run focused and full checks in all three engines, inspect applicable visuals, complete independent review and a separate simplification pass, then satisfy PR CI and merge gates.

## Exclusions and evidence limits

No framework networking, response ordering, pending UI, loading/error component, generated records/options, numbered controls, new dependency or new root export is added. Do not infer totals from returned records. The setter accepts state, not HTML. Applications construct safe DOM records and manage request failures or select presentation themselves. Package publication is excluded. Keep roadmap completion labels unchanged on the feature branch; a separate post-merge documentation PR records completion and final merge evidence.
