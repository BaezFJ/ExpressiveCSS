TreeSelect already routes branch activation to expansion and leaves to FormSelect's native toggle, which keeps multiple selection open. It renders plain label spans, not nested checkbox controls. Its search eligibility and static authoring rule still exclude multiple mode, and its single-select fallback can implicitly choose a leaf after a selected branch.

Use the native `multiple` attribute as the only mode opt-in. Reuse the existing leaf labels, selected fill, native toggle/change handling and search lifecycle. Enter, Space or a label click toggles one leaf and keeps the popup open. Focus movement never changes selection. This follows the modifier-free model in the [APG tree view pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/). Branches remain expansion controls. Normalize selected branches before trigger synchronization in multiple mode rather than adding filtered public getters or another selection store. Keep genuine leaf selections, including disabled authored selections, under native ownership. Mode is chosen at initialization; changing `multiple` later requires destroy/reinitialization, as with FormSelect.

## Requirements

- **R1. Native opt-in and compatibility.** A native `select[data-tree][multiple]` initializes as one TreeSelect through explicit init or AutoInit. It uses existing options, exports, registry and native form ownership. Single-leaf selection remains the default; browser-default controls remain native. An empty multiple select gains no implicit leaf. Preserve single-tree, flat single/multiple and their search behavior.
- **R2. Leaves only.** Only enabled visible leaves can toggle. Branch activation changes expansion only, never selects descendants, changes leaf choices or emits change. Branches have no selected/checked state in the generated tree and remain disabled for native submission. During multiple-mode initialization, native change synchronization, refresh and successful reset, clear selected branch options without selecting a replacement leaf or changing defaultSelected. Use option identity, preserving duplicate-valued leaves. The inherited trigger and getSelectedValues reflect selected native leaves in native order after synchronization. Destroy restores branch disabled attributes while retaining current leaf choices.
- **R3. Toggle and form contract.** A click, Enter or Space toggles that leaf independently, updates native selected state and leaf aria-selected once, and emits exactly one composed native change when its selected-value array changes. Keep the popup, query and focus open through leaf toggles. Focusing or expanding/collapsing branches never changes selected leaves. Choosing leaves under different parents submits both values through native FormData.getAll, with no branch value; deselecting one preserves the other. Search and generated controls contribute no extra form values. Preserve native disabled/required validity and existing invalid-focus handling.
- **R4. Search multiple leaves.** `searchable: true`, including markup options, also works in multiple trees. Reuse Phase 75 leaf-only literal matching, retained ancestors, disabled/no-results behavior and one pre-query expansion baseline. Toggling preserves the active query and selected leaves hidden by later queries. Clearing or closing restores expansion without losing any choice. Filtering and dismissal remain selection-event-free. No select-all, parent propagation, fuzzy matching or new search option is added.
- **R5. Accessible tree state.** Put aria-multiselectable=true on the actual named role=tree, never the presentation/dialog wrapper. Single trees remain false or implicitly false. Keep leaf aria-selected distinct from focus; branches use expanded/group semantics and omit selection state. Reuse existing focus and selected paint, names in the control's own root, RTL, text scaling, forced colors and reduced motion. Retain plain tree label spans; add no nested interactive checkbox or second selection state.
- **R6. Keyboard, pointer and focus.** Reuse tree arrows, Home/End, star, typeahead and mirrored RTL branch arrows without losing selections. Multiple mode requires no modifier to toggle or navigate; range selection and modified-key shortcuts are outside scope. Default nonsearch opening focuses the first selected enabled leaf and reveals its ancestors, or the first enabled row if none; search mode retains Phase 75 search focus and editing rules. Enter in search never chooses or submits. Branch/leaf Enter and Space prevent accidental submission. Keep existing Tab/Shift+Tab dismissal or search traversal, Escape-to-trigger, outside-target focus, autoFocus false, callbacks and delayed-opening focus protection, including native dialogs and open shadow roots.
- **R7. Lifecycle and independent instances.** Refresh re-reads native leaves, options and disabled state, preserves surviving selections, expansion/query/caret and eligible focus using existing policies, and silently normalizes new branches. Native uncanceled reset restores default leaf choices, clears search, closes and restores expansion; canceled reset preserves current state. Scripted selection plus change/refresh synchronizes without invented events. Disabled refresh closes and later enable/refresh recovers. Required validation stays native. Two instances remain independent; destroy/reinitialization cleans generated elements, listeners and timers. Do not support switching single/multiple mode through refresh.
- **R8. Authoring and delivery.** Remove the obsolete single-only TreeSelect prohibition from semantics.json and its negative fixture while preserving element, optgroup, parent and naming rules. Static checks never initialize components. Update tree-select docs with a live multiple example, activation/close/form/search/lifecycle contracts and native markup, shared Select guidance where stale, llm.md, changelog and the existing tree decision record where supported. Preserve historical source-review pins. Regenerate semantics/skill/MCP outputs from sources, review gzip from JS109888/CSS90945, and complete focused, mutation, three-engine, contributor/MCP/package and inspected visual checks. Independently review/fix and separately simplify; merge only after exact-head CI, conversations, current master and clean-worktree gates pass.

## Scope and evidence limits

No choosable branches, selection propagation, range/select-all shortcuts, generated checkboxes, remote loading, networking, new component, public option, selection store, runtime dependency or release. Styles change only if the existing selected/focus treatment fails the multiple-tree checks. Physical devices, native browser zoom, physical OS input including IME and spoken screen-reader output are unavailable. Synthetic composition guards and emulation do not establish those capabilities.
