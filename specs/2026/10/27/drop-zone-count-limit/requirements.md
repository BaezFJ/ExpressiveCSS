## Requirements

- **R1. Independent count constraint.** Enabled native file inputs inside their nearest drop-zone enforce valid data-max-files without requiring type/size opt-ins or a file list. Parse trimmed decimal digits as a positive safe integer; other values are inactive. Count native FileList entries, including duplicate filenames. Exactly the limit passes; more fails. Empty optional choices remain valid, while required-empty native invalidity stays effective. Unmarked inputs retain their existing behavior. Do not add multiple automatically. Disabled controls/fieldsets remain inactive; refresh through Forms.validateField after scripted enabling/constraint changes.
- **R2. Whole-selection native rejection.** Too many files invalidate the complete retained selection and block ordinary native form submission. Never filter, replace, upload, accept or imply an accepted subset. Safely list every selected file when a list exists. Reuse native custom validity ownership and invalid/aria-invalid state, preserving unrelated pre-existing/replacement application messages and required/native-bypass/error-summary behavior.
- **R3. Shared accessible feedback and precedence.** Count opt-ins require the existing direct data-error area with role=status and aria-live=polite. Preserve descriptions and author ids, appending the error id once. Write real text without moving focus. Type failure wins, then size, then count; use nonempty data-error-count for count or a fallback naming the exact count limit. Keep existing type/size localization unchanged. Reflect remaining native/application errors when file rules pass, otherwise hide/clear valid feedback. Extend the existing error/focus/typography selectors and static live-status rule, preserving the public rule id and never initializing components during static checks.
- **R4. Shared delivery and snapshots.** Browse and native drop share input/change handling in dynamically inserted zones and open shadow roots. A changed count-rejected selection reports one bubbling, composed, noncancelable expressive:reject from its nearest wrapper with `{ input, files, rejected, reason: 'count' }`. Both arrays contain every selected File but are independent from each other, native files and deduplication metadata. Preserve type/size reason/subset behavior when those earlier rules fail. Native pairs with identical File identities and effective constraints report once; a changed effective count can report after input/change, while equivalent decimal limits deduplicate. Silent validation/reset report no rejection; newer reentrant selection updates remain authoritative.
- **R5. Recovery and isolation.** Valid/exact-count replacement, clearing, removing/invalidating the count limit followed by validation, and successful reset release only framework-owned file validity. Preserve application custom validity through rejection/recovery/reset. Canceled resets preserve files/list/error/drag state. Reuse deferred cleanup, native form ownership including external associated controls, handled shadow-form reset and newer-selection protection. Keep type-only, size-only, independent and nested zones compatible and isolated.
- **R6. Verified guidance and merge.** Update docs, llm.md and changelog with count-only/combined examples, parsing/boundaries, count snapshots and precedence, script/reset ownership and server validation. Regenerate semantics/skill/MCP data. Review gzip deltas from JS 109451 and CSS 90904. Run focused Node/browser/static checks, a count-boundary mutation, full contributor checks, MCP and isolated packages. Inspect four docs layouts and count-feedback light/dark captures, complete independent review/fixes and separate simplification, then merge after exact-head CI/conversation/current-master/clean-worktree gates pass.
