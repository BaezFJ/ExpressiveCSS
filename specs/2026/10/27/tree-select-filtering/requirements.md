## Requirements

- **R1. Opt-in and compatibility.** `TreeSelect.init(select, { searchable: true })` and existing data-tree-select-options enable search on enhanced single selects with data-tree. Search defaults off; default tree, flat single/multiple search, native browser-default controls, exports and constructor/types stay compatible. Multiple-tree search remains unsupported until Phase 76. Reuse the current component/registry, FormSelectOptions, Menu, i18n.searchLabel and i18n.noResults; add no public option or runtime dependency. Keep new functions below complexity five.
- **R2. Leaf filtering and ancestry.** Trim query edges, lowercase query and each leaf's trimmed text, and match a literal substring. Preserve internal whitespace and accents; do not search branch labels, option values, images or regexes. Keep matching leaves and every ancestor in document order, revealing and opening matching paths even from previously closed branches. Hide all other generated rows; navigation, typeahead, branch entry, sibling opening and activation must exclude hidden rows. Disabled matches remain visible but cannot be selected or focused; they count as matches. A branch-label-only match shows no unrelated leaves. No matches shows safe localized status text. Filtering never removes or disables native options.
- **R3. Restore expansion.** On transition from empty to nonempty query, save open branch values once, using the existing refresh identity policy. Preserve this baseline across subsequent queries, manual temporary branch toggles and refresh. Clearing restores all surviving branches to that saved state and shows all rows. Every close also clears search/status and restores expansion before reopening. A removed saved branch is ignored; newly added branches have no saved open state. An empty query without an active search session leaves ordinary expansion alone.
- **R4. Native selection and submission.** Typing, clearing, filtering out a selected leaf, no results and dismissal do not change the native value, trigger text or emit change. Search has no name and never contributes form data. A visible enabled leaf uses the existing selection path, changes exactly once when its native value changes and closes the single-leaf popup. Branches remain navigation controls, disabled for native submission with no parent-to-child selection propagation. Preserve native required/disabled validity, error descriptions, form reset and branch-attribute restoration on destroy.
- **R5. Named search and tree.** Search mode's read-only trigger controls a named nonmodal dialog with aria-haspopup=dialog, containing a labelled search input, polite nonselectable status and separately named role=tree. Retain nested treeitem/group/expanded/selected/disabled semantics; never put search inside a treeitem or turn the tree into a listbox. Names and IDs resolve in the control's own document/shadow root, honoring authored aria-labelledby/aria-label and labels. Search label is independent of placeholder. Render text safely and clear stale active references. Default trees retain their presentation/tree popup contract.
- **R6. Keyboard and focus.** Default opening focuses search; autoFocus false preserves outside focus and leaves search reachable by normal traversal. Opening completion preserves focus already inside the popup. Typing, paste, Space, Home/End, horizontal keys and composition retain native search editing. Enter in search neither submits nor chooses a leaf. ArrowDown/ArrowUp enter the first/last enabled visible tree row, staying in search if none. In rows retain existing nonwrapping tree Up/Down, Home/End, RTL branch arrows, star, typeahead and Enter/Space branch-toggle/leaf-choice behavior. Tab from search enters the first enabled row; Shift+Tab from any row returns to search. Tab from a row or search with no enabled rows closes and advances after the trigger. Shift+Tab from search closes to the trigger. Escape closes to the trigger; outside dismissal preserves the outside target. Preserve callbacks and prevent duplicate Menu/tree key handling or search-click cancellation.
- **R7. Refresh, reset and teardown.** Refresh rebuilds/reapplies an active query while preserving its original expansion baseline and search focus/caret. Keep focus on a surviving enabled visible row; otherwise use an enabled visible row, search if none, or the trigger for default trees. Disabled refresh closes/prevents opening until enabled and refreshed. An uncanceled native reset closes, clears query/status, restores pre-query expansion and default value, and synchronizes the trigger; cancellation retains query/selection/expansion. Destroy/reinitialization removes all generated controls/listeners/timers and extra Menu instances and restores native branch disabled attributes, labels and tab index. Support dynamic AutoInit, open shadow roots and native modal placement; tests always clean up in finally.
- **R8. Styling, guidance and delivery.** Reuse search/tree Sass in forms/_select.scss for a stationary search/status and independently scrolling results, visible hidden-row removal, rem-based control/text scaling, shared typography/theme/motion tokens, RTL and forced-colors focus. Update tree-select docs with a live search example and full contracts, the shared options/tree sections in llm.md, changelog and existing tree decision record where justified. Correct stale shared search exclusions without adding Phase 76 behavior. Runtime-generated search roles need no author semantics rule; preserve static semantics and regenerate source-derived guidance. Measure gzip changes from JS 109553/CSS 90909. Complete focused/mutation/real-browser/full contributor/MCP/package checks, inspected four-layout tree/select comparisons and search-feedback light/dark checks. Independently review/fix, separately simplify and merge only after exact-head CI/conversation/current-master/clean-worktree gates pass.

## Scope and limits

No multiple-leaf behavior, choosable branches, parent selection propagation, remote/lazy loading, fuzzy matching, highlighting, new count announcements, observer, clear button, new component or runtime dependency. Introduce only narrow FormSelect search hooks with real flat/tree consumers; TreeSelect owns hierarchy filtering/expansion/navigation. Preserve default tree and flat search behavior, including the just-merged delayed-opening focus repair. Physical devices, native zoom, physical OS input and spoken screen-reader checks are unavailable; emulation does not establish them. Keep roadmap labels unchanged here; the separate final docs PR records completion, lasting rules and actual merge evidence.
