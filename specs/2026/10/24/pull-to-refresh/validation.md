# Validation: pull-to-refresh

Roadmap phase: Phase 36, pull-to-refresh. Requirements are in [requirements.md](requirements.md) and the work order in [plan.md](plan.md).

The agent ran every check below on 2026-10-24 on branch `feature/2026-10-24-pull-to-refresh`. All 13 cases pass in all three engines, 39 runs in total. Tests run against built bundles, so run `npm run build` first, and run suites one at a time, since parallel browser runs flake.

## Automated checks

V1 to V7 are Playwright cases in a new file, `tests/pull-to-refresh-browser.test.js`, run with `node --test tests/pull-to-refresh-browser.test.js` in Chromium, Firefox and WebKit. Each case closes its page in a `finally` block, and V1 and V7 also call `destroy()`.

Touch input: Chromium drives real touches through CDP `Input.dispatchTouchEvent` in a `hasTouch` context, as `tests/sheet-touch-browser.test.js` does. Firefox and WebKit get `touchstart`, `touchmove` and `touchend` events dispatched from the page in a `hasTouch` context. A probe on 2026-10-24 found Firefox has the `Touch` constructor and WebKit does not, so both get a `TouchEvent` whose `touches` list is defined on the event.

Fixture: a `.pull-to-refresh` list of 40 rows in a 400 by 300px box with `overflow-y: auto`, holding a contained loading indicator and a `[data-refresh]` button, started by `AutoInit()`. A second copy has no scroll of its own and holds 120 rows, so the page scrolls. A listener counts `expressive:refresh` events.

V1 is the acceptance check from the roadmap. V2 to V7 are the short regression cases the user asked for, one per behavior.

V1 and V2 also count the moves the component cancelled, through a passive document listener: a pull cancels its moves, and a sideways or scrolled-down drag cancels none.

V2 to V7 passed on the code from group 1, which already handled their behavior, so no run saw them fail. A source mutation run on 2026-10-24 stood in, in Chromium. Removing the busy guard failed V3. Removing the scroll check failed V2 and V5. Reading only the element's own scroll failed V5. Removing the reduced-motion rule failed V6 once the `:root` override was in. Skipping the cleanup in `destroy()` failed V7. Removing the button handler failed V4. Treating `touchcancel` as a release, and pulling on any downward move whatever its sideways travel, failed V2. Leaving a settled `waitUntil()` promise without effect failed V1. The first run found a scroll check in `touchstart` that the first move repeats, so the duplicate was deleted. After the review fixes, a second mutation run caught each of these: ignoring a scrolled-down inner scroller (V10), keeping a pull after a second finger (V11), dropping `preventDefault()` or making `touchmove` passive (V1), skipping the pull cleanup in `destroy()` (V7), and letting an earlier refresh's promise end the next one (V12). A third run caught each of the later fixes failing: a throwing callback leaving the refresh running, a swallowed rejection, a missing start announcement, a finish announced with nothing running, a negative threshold kept, and the status region left after `destroy()`.
